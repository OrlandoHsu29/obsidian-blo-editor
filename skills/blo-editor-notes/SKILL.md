# Blo Editor 笔记

Blo 直接编辑 Markdown。标准标题、任务、表格、公式和代码块已经能在 Blo 中呈现。块缩进、列表折叠、自定义编号和部分媒体、表格样式由额外元数据保存。

## 选择写法

1. **起草**。新笔记通常用普通 Markdown 组织结论、正文和下一步。优先用 H1～H4 分章、列表表达步骤、表格比较同类信息。小改动直接改目标块。参照[基础稿](assets/example-draft.md)。
2. **明确哪一处值得增强**。正文、表格和代码需要随同一个父项移动时，使用真实父子块。长步骤需要收起时，使用可折叠列表。关键警告用提示框，局部状态可用颜色加文字。需要空间布局和手动编辑时再创建可编辑画板。用户明确要求丰富排版时，在同次交付中应用这些增强。
3. **只展开相关资料**。按下表查阅相关小节。直接在目标区域落地，再检查保存后是否仍能编辑。已有 Blo 笔记以原结构为起点。

## 写入要点

- 使用用户指定的笔记和目标路径。需要新建附件时，按目标库的附件位置和现有相对路径处理。
- H1～H4 在大纲中，H5 是局部子标题。标题块深度为 0。正文、列表、表格、引用、代码和媒体可以按深度组成可移动的父子块，移动父块时保留其后的连续子块及相对深度。
- 简单草稿可以没有 `wysimark-*` 注释。引入块级元数据时，按[格式协议](references/format.md#块容器与深度)标记每个顶层块，并只在需要的块写扩展字段。保留已有元数据、frontmatter、块 ID、链接和附件路径。
- 已有笔记按目标做局部修改。使用支持 Blo/Slate 的编辑接口时，通过模型操作保留撤销。直接改文件时，写入前重读，确认源文件已保存且没有并发变更。只能聊天时，交付可保存的完整内容和相对路径。

## 检查交付

检查关键结论能否快速找到、层级和编号是否正确、折叠里是否只放次要内容。核对元数据能解码、标记紧邻对应块、链接及附件真实存在。能打开 Blo 时检查目标样式和保存重开。交付时说明实际验证到哪一步。
