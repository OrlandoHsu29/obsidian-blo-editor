# Blo 文件协议

本说明对应 Blo Editor 0.1.32 的源码协议。`wysimark-*` 是兼容已有笔记的格式名，不要替换成 `blo-*`。安装的插件出现不同保存形式时，优先保留原文件并核对当前实现。

## 块容器与深度

每个顶层 Slate 块在文件中使用以下结构，注释独占一行，前后用空行隔开：

```text
<!-- wysimark-block:v1 URI_ENCODED_JSON -->

该块的 Markdown 内容
```

实际写入时用 JavaScript `encodeURIComponent(JSON.stringify(metadata))` 替换 URI_ENCODED_JSON，不要把占位字样写入笔记，不要使用 Base64 或 HTML 实体。完整示例见 assets。解码示例：`{"depth":1}` → `%7B%22depth%22%3A1%7D`。

| 字段 | 保存含义 |
| --- | --- |
| `depth` | 0～32 的整数；0 是顶层。新建笔记从 0 开始，每次增加至多一级，确保有前面的父块 |
| `collapsed` | `true` 折叠有子块的有序/无序列表父项；不对普通段落或任务列表声称支持折叠 |
| `numbering` | 有序项的 `continue` / `restart` / `explicit`，延续、从 1 重启或明确起点 |
| `start` | 有序项的明确数字起点；需要自定起点时配合 `explicit`。延续时省略 |
| `headingStyles` | 标题显示设置数组，元素为 `{path,style,enabled}`，style 为 `hash` 或 `number` |
| `subtitles` | 旧格式子标题节点路径数组；保留已有值，新建直接使用 H5 |

深度作用于该标记后、下一块标记前的内容。虽然解析器容许一个区段恢复多个节点，新建时一个标记对应一个块，更易稳定保留层级。引用内部的多段内容、表格全部行、围栏代码全部行属于一个块。子块位于父块之后，持续到第一个深度小于等于父块的块；不是把任意 HTML 嵌套进段落。

有元数据时，列表 Markdown 在区段中从 0 缩进开始，真实缩进写进 depth。不要再给列表加四空格而造成双重缩进；普通段落用空格缩进还可能变成代码。没有任何扩展结构的普通笔记可以只用 Markdown；要求块关系、折叠或特殊标题状态时必须保存标记。

## 标题与编号

`#`～`####` 对应大纲标题；`#####` 是子标题。标题块 depth 一律为 0，包括被列表包装的标题；不要照搬旧示例中缩进的标题。

- 普通标题：`## 方案`；默认 hash 样式。需要明确记录开关时使用 `headingStyles:[{path:[],style:"hash",enabled:true}]`。
- 编号标题：区段正文为 `1. ## 方案`，它是含 H2 子节点的有序列表块。元数据可设 `{depth:0,numbering:"continue",headingStyles:[{path:[0],style:"number",enabled:true}]}`。`[0]` 指列表中的标题，普通标题的路径为 `[]`。
- 不要把渲染后的 `1.2.3` 写成标题文字；用简单有序项标记和标题级别，让插件算多级编号。仅实际启用编号的上级参与编号，正文/代码不必重启序列。
- 禁用某标题的前缀时保存 `enabled:false`，不要删除用户保存的偏好。H5 可放在有序项中显示字母序号，但仍不进入大纲，不使用 H1～H4 的编号开关代替子标题规则。

## 正文、样式、公式与链接

| 内容 | 写法 |
| --- | --- |
| 加粗 / 斜体 / 删除线 | `**内容**` / `*内容*` / `~~内容~~` |
| 下划线 | `<u>内容</u>` |
| 行内代码 | 反引号；含反引号的内容选择更长的分隔符 |
| 字色 | `<span style="color:#1677FF">内容</span>` |
| 背景强调 | `<span style="background-color:rgba(22,119,255,0.14)">内容</span>` |
| 颜色组合加粗 | `<strong><span style="color:#DF2A3F">重点</span></strong>`，标签避免相邻 Markdown 分隔符歧义 |
| 任务 | `- [ ] 待办` / `- [x] 完成` |
| 无序 / 有序列表 | `- 要点` / `1. 步骤`；使用块元数据时由 depth 保存真实缩进 |
| 引用 / 提示 | `> 引用`；Obsidian callout 如 `> [!note]` 可置于同一引用块 |
| 分割线 | 独立的 `---` 块，与前后内容空行分隔；不要紧贴正文形成 Setext 标题 |
| 行内 / 块公式 | `$E=mc^2$` / 独立行的 `$$` 围栏；分隔符比源码中连续美元符号更长 |
| 内部链接 | `[[目录/笔记]]`、`[[目录/笔记#标题|显示文字]]` |
| 块链接 / 块嵌入 | `[[目录/笔记#^块ID]]` / `![[目录/笔记#^块ID]]`，用于引用具体块而非整篇笔记 |
| 外部链接 | `[文字](https://example.com "悬停说明")` |
| 附件引用 | `![[附件/图.png|640x360]]`；需要描述时可用 `![描述](附件/图.png)`，含空格地址用 `<...>` 包裹 |

固定前景色：红 `#DF2A3F`、橙 `#ED740C`、黄 `#AD8500`、绿 `#00A650`、蓝 `#1677FF`、紫 `#7C3AED`、灰 `#787878`。默认正文不指定字色，近黑/近白会映射回主题；中性底色也会被清理。清除格式时去掉显式颜色，包括表格内的颜色。只使用 color/background-color，任意字号、字体、行距、字距不会按粘贴样式保留。

段内硬换行用行末两个空格加换行；新块使用空行及新块标记。代码使用带语言的围栏，内容含围栏时延长外层围栏。不要向代码源码内添加字体标签。脚注用 `[^id]` 与 `[^id]: 内容`，保留标识符。

块 ID 使用 Obsidian 原生 `^id`，仅包含英文字母、数字和连字符，在一篇笔记中保持唯一。普通段落、标题在末尾加 ` ^id`；单个列表项在该项第一行末尾加 ` ^id`；引用、表格、代码、公式和其他结构块后空一行，独立写 `^id`，再空一行。这些标识符不是可见正文，不写进 `wysimark-block:v1` 的 JSON。已有 ID 应复用，修改文字或移动块时保留，复制出新块时不要重复原 ID。块菜单的「复制块链接」可自动生成 ID 并保存；新笔记中粘贴链接可跳转，加 `!` 可嵌入块内容。不要为没有被引用的每个块强行添加 ID。

例如技术笔记可把术语比较放进表格，将变量名写成行内代码，将示例写入 `python` 围栏代码块，把 $O(n)$ 这样的复杂度写成行内公式，并用引用块补充边界条件。这些内容可以出现在同一篇笔记中，按各自类型序列化，不必把整篇笔记套进一个代码围栏。

## 表格

使用 GFM 管道表格。对齐为 `:---`、`:---:`、`---:`。单元格换行用 `<br>`；任何单元格里的管道，包括公式、行内代码及 wiki 链接里的 `|`，都需转义为 `\|`，避免多出列。

标题行/列在表格前写独立标记：

```text
<!-- wysimark-table:v1 %7B%22headerRow%22%3Atrue%2C%22headerColumn%22%3Afalse%7D -->

| 项目 | 内容 |
| --- | --- |
| 输入 | 资料 |
```

若表格有块缩进，先是 block 标记，再是 table 标记，然后表格；table 标记与表格之间不要插入其他内容。GFM 分隔行仍要保留，即使 `headerRow:false`。不要发明合并单元格、宽度或任意行列样式字段。

## UI 操作提示

文件协议不等同于键盘模拟：正文 Tab/Shift+Tab 改块缩进；代码内 Tab 改源码缩进，选中整个代码块后才改块缩进；表格 Tab 切换单元格。标题不能缩进。斜杠菜单支持 `/表格`、`/画板`、`/公式`、`/链接`、`/附件`；附件默认嵌入，链接始终插入文字链接。需要界面操作时先确认焦点、选区和插件依赖，不能把输入 `/画板` 的字面文本当成已创建附件。
